== v3.11 (upcoming)

=== New Features

* **Section Round-trip**: The DOCX→AsciiDoc converter now reconstructs the standalone `[section]` marker from a document's section breaks, so an AsciiDoc→DOCX→AsciiDoc round-trip is a fixed point. Each section's own `[header]`/`[footer]` blocks are emitted at the start of that section's span — right after its `[section]` marker — instead of collecting all headers at the top and all footers at the document end, which rebound them to the wrong section on re-conversion. Empty header/footer parts are preserved, keeping the empty blocks that break inheritance.
* **Section Properties**: A new span-scoped `[section-properties]` block declares a section's layout (page size, margins, orientation, columns, document grid, break type, different-first-page), bound like `[header]`/`[footer]` to the section whose span it appears in. The DOCX→AsciiDoc converter emits it for every section (replacing the old dead `// section {...}` comment), so page setup round-trips losslessly; this emission can be disabled for tests that do not verify those values (`toAsciidoc(pkg, skipComments, false)`). Property values accept two equivalent formats, usable freely and mixable: nested brace maps (`pgSz={w=11906, h=16838}`) and dotted paths (`pgSz.w=11906`, `pgSz.h=16838`).

=== Improvements and Fixes

* **Text Rendering**: Delimited blocks (`[header]`, `[footer]`, quotes, etc.) no longer emit a blank line inside their closing delimiter, so rendered text matches its AsciiDoc source form exactly.

== {proj}/v3.10[v3.10]

=== New Features

* **Multi-section Documents**: A standalone `[section]` marker now ends the current document section. Headers and footers declared since the previous marker bind to that section, and a section that declares none inherits the previous section's ones, matching Word's per-reference-kind inheritance semantics ("Link to Previous" for each header/footer part). An **empty** `[header]`/`[footer]` block references a distinct empty part and breaks inheritance.
* **Text Round-trip**: The Text renderer outputs the `[section]` marker back, so section breaks survive an AsciiDoc→DOCX→AsciiDoc text comparison.

=== Improvements and Fixes

* **API Compatibility**: Restored the `saveSvgAsImage(String, Path, int, Color)` overload of `AsciiDocCompiler`, accidentally dropped by the transcoding-hints refactor in v3.9.
* **Backward Compatibility**: Documents without any `[section]` marker behave exactly as in v3.9, and the DOCX→AsciiDoc converter output is unchanged.

== {proj}/v3.8[v3.8]

=== New Features

* **AlternateContent Support**: Added `AltContentRecorder` to handle `AlternateContent` elements in DOCX files, improving placeholder processing within these blocks.
* **Pict Element Support**: Introduced `PictRecorder` for better processing of DOCX `pict` elements.
* **SVG Icons**: Added a set of SVG icons and an `Icon` enum for predefined identifiers.
* **Architecture Decision Records**: Migrated ADR 001 to AsciiDoc and integrated it into the documentation site.

=== Improvements and Fixes

* **Documentation Structure**: Relocated ADRs and examples to `src/site/asciidoc` for better alignment with Maven site standards.
* **Java 25**: Updated the project to require Java 25.
* **Refactoring**: Simplified `DocxToAsciiDoc` logic and consolidated package structures (merged `core.core` into `core`).
* **CI/CD**: Added initial Renovate configuration and updated various GitHub Actions.

=== Dependencies

* **maven-skin**: Updated to v1.0.9.
* **docx4j**: Updated to v11.5.14.
* **jsoup**: Updated to v1.22.2.
* **Maven Plugins**: Updated `maven-site-plugin` to v3.22.0, `jacoco-maven-plugin` to v0.8.15, and `pitest-maven` to v1.25.5.

== {proj}/v3.7[v3.7]

=== New Features

* **Initial Docx-to-AsciiDoc Conversion**: Core functionality for converting DOCX documents to AsciiDoc format.
* **Lightweight Converters**: Support for rendering AsciiDoc to HTML, SVG, and Text.
* **AsciiDoc Preview**: AsciidoctorJ extension for embedding document previews.
